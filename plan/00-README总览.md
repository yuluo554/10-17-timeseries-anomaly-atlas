## 决策记录

| 编号 | 弃选项 | 弃因 | 采纳 |
| --- | --- | --- | --- |
| D1 | 深度学习检测器（自编码器/LSTM/Transformer） | 不可解释；训练不可复现（随机种子、框架版本、硬件差异），直接违背"同一 run-spec 重算出同一集合"的复算纪律；且引入 GPU/重依赖，与单文件离线交付冲突 | 首期只做可解释、确定性的统计与规则检测器（滚动中位数+MAD、滚动 IQR、STL 残差、规则型/CUSUM） |
| D2 | 通用图表选型/美化能力 | 与已占的视觉/渲染语义赛道正面相撞；"画得好看"不是本题卖点，会稀释护城河 | 图形只为异常语义服务：异常带、缺口纹理、峰值、Episode 卡片、small multiples、密度热条 |
| D3 | 依赖 statsmodels / pyod / darts | 重依赖链条（pandas/scipy/numba 等），离线打包与浏览器镜像成本高；库层已极卷，薄封装无差异化 | 纯标准库自实现检测核心（**D6 细化：连 numpy 也不引入**，理由是归约顺序是实现细节、破坏跨语言逐位复算）；STL 用经典可复现实现，周期由自相关估计或用户声明 |
| D4 | 把"浏览器复算"做成可选演示或截图说明 | 复算正是本题护城河；做成可选项，产品立即退化为 pyod/darts 的薄封装 + 好看图表 | M3 浏览器复算定为**硬门禁**：未通过复算的 HTML 不构成交付物 |
| D5 | 报告数字由模型自由撰写 | 模型幻觉会污染"可复算档案"的信任基础，一个编造数字即可摧毁整份档案 | 数字白名单：报告中每个数字必须命中 `facts.json`，未命中即失败并列出上下文 |
| D6 | 引入 numpy 做向量化检测（题面 M2 允许，但未要求） | `np.mean/sum/dot/median` 的归约顺序是实现细节（分块求和跨版本可变）；而复算门禁要求 Python 与 JS 逐位一致 → 该风险面必须整体消除 | 纯标准库 + 显式循环（操作序列可镜像）；详见 `plan/06` D6/D9 |
| D7 | 规范 JSON 里直接写浮点字面量 | CPython `repr` 与 JS `Number#toString` 的最短往返表示在极端情形不保证同串 | 规范 JSON **只含整数与字符串**：浮点在哈希边界定点化为整数（半偶舍入，`quant_decimals=6`），十进制展示串由整数构造（`data/README.md` §4.3） |
| D8 | 把"缺 Node"并入 exit 2、把 exit 3 复用于"缺依赖" | 语义混用使用户分不清"我输错了"与"我环境缺东西"；"阶段未就绪"的退役流程也会失去单一语义 | 退出码契约 0/1/2/3/4（3 = 阶段未就绪，骨架期占位、随模块落地整项退役；**M5 退役最后一个键后常量本身也已删除**，现行契约 = 0/1/2/4）；详见 `plan/02` §5、`plan/06` D8/D23 |
