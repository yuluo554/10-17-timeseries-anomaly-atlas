## 1. 介绍

时间序列异常检测在算法层面已经非常成熟：pyod 提供通用异常检测器集合，darts 提供时序建模与检测，PyPOTS 提供部分观测时序学习。它们都是**库/引擎**——能力齐全，但交付物止步于"函数返回一个标签数组"。

真正消耗分析师时间的不是"跑出标签"，而是**事后解释与复核**：

- 这条序列里到底有几段异常？每段从哪一行开始、到哪一行结束？
- 是哪一类检测器、用什么窗口和阈值把它判出来的？得分多少？
- 换一个人、换一台机器、换一次运行，还能不能得到同一批异常点？
- 把这份结论发给同事时，对方凭什么相信图上的色块不是"画上去的"？

现有工具的回答方式通常是：导出一张静态图，或启动一个需要部署的 Dashboard。**没有一种交付物同时满足"单文件、可离线、每个异常可追溯、且能当场复算"**。

本题要求做一个**时序异常标注可视化 Skill**：输入一份 CSV 时间序列，输出一份可直接双击打开的单文件 HTML——主序列、异常区间带、峰值标记、缺口纹理、Episode 卡片、多指标 small multiples 与异常密度热条；每个异常区间都携带检测器名、参数、得分、源行号与 `episode_id`；HTML 内置同一套算法的 JavaScript 镜像与内联原始数据，加载时当场重跑，只有重算出的异常集与构建时 `sha256` 一致，才显示 **VERIFIED** 徽章。

### 1.1 模型分工（表达层 vs 计算层）

- **确定性代码负责（计算层）**：时间解析与数据剖面、检测器打分、Episode 合并、严重度排序、run-spec 生成、规范 JSON 序列化与 `sha256`、JavaScript 复算镜像、报告数字白名单校验。
- **模型只负责（表达层）**：数据语义判断、阈值取舍的**理由**（最终取值必须写回 run-spec，因而可复算）、Episode 命名与可能原因（必须引用 `episode_id`）、报告叙事。
- **模型禁区**：不得手改异常点，不得新增未检测到的点，不得在报告中写出未命中 `facts.json` 的数字。

## 2. 差异化（必须写清）

视觉类 skill 赛道已被两类语义占据：

1. **渲染语义**——"把已有数据画得好看"：图表选型、配色、版式、交互；
2. **流程挖掘语义**——"把事件日志挖成流程模型"：DFG、变体、瓶颈、符合度。

本题不碰这两块。本题卖的是**异常 episode 的语义与可复算性**：

- **Episode 语义**：异常不是一个孤立的点，而是一个有起止、有持续时长、有峰值、有触发检测器、有源行号的区间对象；
- **可复算性**：异常集不是"某次运行的截图"，而是由 run-spec 唯一决定的集合；同一 run-spec 必须重算出同一 `sha256`，并且这个重算发生在**读者的浏览器里**，而不是作者的机器上。

如果只做"检测 + 画图"，产品就是 pyod/darts 的薄封装，题目不成立。护城河是 **M3 浏览器复算门禁**：它把"图好看"降级为附属品，把"结论可验证"升级为交付前提。

## 4. 任务要求（首期 5 个模块）

每个模块的"输入 / 输出 / 确定性纪律 / 验收"即完成口径，缺一不算完成。

### M1 数据契约与剖面

- **输入**：用户自备 CSV（至少含时间戳列与数值列；可选 `series_id` 支持多指标）。
- **输出**：
  - `profile.json`：时间解析结果、时区与 DST 处理记录、采样节奏（间隔分布/主导节奏）、重复时间戳清单、缺口区间、零值段与缺失段；
  - 数据质量卡（HTML 首屏可读，同时在 JSON 中结构化）。
- **确定性纪律**：剖面是纯规则计算，不调用模型；所有区间与计数由同一套解析规则得出；JSON 键排序后落盘。
- **验收**：同一 CSV 连续两次运行，`profile.json` **byte-identical**；异常输入（空文件、缺列、时间不可解析、数值不可解析）返回明确错误码并指出源行号。

### M2 检测内核与 Episode 语义

- **输入**：通过 M1 的序列 + run-spec 参数。
- **输出**：
  - 首期 4 类检测器：
    1. 滚动中位数 + MAD 稳健 z；
    2. 滚动 IQR 越界；
    3. STL 残差 z（周期由自相关估计或用户声明；纯 Python/numpy 经典 STL，不依赖 statsmodels）；
    4. 规则型（静态阈值 / 百分比突变 / 连续缺失或零值段 / CUSUM 两窗均值漂移）；
  - Episode 合并：相邻异常点按 `max_gap` 合并为区间，计算 `start / end / duration / peak_score / n_points / detector`，按严重度确定性排序并分配 `episode_id`；
  - `run.json`（全部参数）→ `anomalies.json`（异常集）→ 异常集 `sha256` 指纹。
- **确定性纪律**：规范 JSON（键排序、浮点定点格式化）是唯一哈希输入；参数、合并间隙、排序键、指纹算法**一处定义**（见 `data/README.md` §4）；重复运行必须同哈希。
- **验收**：固定 fixture 的异常集与 `sha256` 固化在测试里；修改任一检测参数、`max_gap` 或周期声明，哈希必须改变（"改参数必须改哈希"写入断言）。

### M3 浏览器内复算验证器（硬门禁）

- **输入**：构建时导出的原始数据（内联进 HTML）、`run.json`、构建时异常集指纹。
- **输出**：HTML 加载时在浏览器内用**手写 JavaScript 镜像**对同一份内联原始数据重跑同一套检测算法，规范化后计算 `sha256`，与构建时指纹逐位比较；同时做逐点集合比较。一致显示 **VERIFIED**；不一致显示红色 **MISMATCH**，并指出首个差异点（时间戳、行号、期望值、实算值）。
- **确定性纪律**：JS 镜像与 Python 内核共享同一份算法口径说明；浮点格式化与键排序规则必须一致；复算用的数据就是 HTML 内联数据，不发起任何网络请求。
- **验收**：故意篡改一个内联数据点，徽章必须变红并指出首个差异点；正常产物在断网环境下打开必须显示 VERIFIED。
- **强制条款**：M3 是**硬门禁**，不是可选演示。没有浏览器复算通过，M4/M5 的产物一律视为未完成。

### M4 单文件标注图

- **输入**：`profile.json`、`run.json`、`anomalies.json`、原始序列。
- **输出**：单个 HTML 文件，包含：
  - 主序列 + 异常带 + 峰值标记 + 缺口纹理（缺口必须与正常低值可区分）；
  - Episode 卡片：局部放大、阈值线、触发检测器、得分、源行号、`episode_id`；
  - 多指标 small multiples + 异常密度热条（按时间分箱的 Episode 覆盖度）；
  - 阈值灵敏度滑杆：前端确定性重算（同一 JS 内核），滑杆值同步显示为 run-spec 片段；
  - 打印样式：黑白打印仍可区分异常带与缺口纹理，卡片不截断。
- **确定性纪律**：图形坐标、分箱、颜色映射全部由数据与固定规则计算；不使用随机布局；同一输入两次渲染的可见几何一致。
- **验收**：断网可用；无外链字体、无外链脚本、无 CDN；`grep` 断言 HTML 中不存在 `http://` / `https://` 资源引用；打印样式可读。

### M5 报告层与数字白名单

- **输入**：模型撰写的摘要、Episode 命名与可能原因、叙事文本；内核导出的 `facts.json`。
- **输出**：报告区（HTML 内）+ 通过白名单校验的文本。
- **确定性纪律**：
  - 模型写摘要、命名、原因时必须引用 `episode_id`；
  - 报告中出现的每个数字（异常数、最大 z、持续时长、峰值、行号等）必须命中 `facts.json` 中的一条事实记录；
  - 未命中即失败，报告生成中止并列出未命中数字及其上下文。
- **验收**：注入一个编造数字（例如不存在的异常数量或不存在的峰值），门禁必须拦截并指出该数字；模型不得借"润色"之名改动异常点或新增点。

### 扩展项（首期明确不做，仅留路线图）

- **token replay 式流程分析**：把 episode 序列当作过程做回放/符合度——语义跨赛道，首期不做；
- **实时流式**：首期只做离线 CSV → 单文件档案，不做常驻监控与告警推送；
- **深度学习检测器**：不可解释且违背复算纪律，首期不做，也不留半成品接口以免被误认为已支持。

## 9. 验收总则与术语

- **Episode**：由相邻异常点按 `max_gap` 合并得到的异常区间，携带起止、时长、峰值得分、点数、检测器与 `episode_id`。
- **run-spec**：一次检测运行的全部参数与算法版本，落盘为 `run.json`；是复算的唯一依据。
- **规范 JSON**：键排序、浮点定点格式化、稳定编码的 JSON；其字节序列是 `sha256` 的唯一输入。具体规则见 `data/README.md` §4。
- **facts.json**：内核导出的数字事实台账，M5 白名单的唯一权威来源。
- **VERIFIED / MISMATCH**：浏览器复算结果与构建时指纹逐位一致 / 不一致；不一致必须给出首个差异点。
- **完成定义**：模块的"输入 / 输出 / 确定性纪律 / 验收"四项同时满足；任何一项缺失即未完成。所有数字口径只在 `data/README.md` §4 定义一次，题面、文档、报告均引用而不复写。
