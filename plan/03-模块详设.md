# plan/03 模块详设（题面 M1–M5 × 源码模块）

题面模块的"输入 / 输出 / 确定性纪律 / 验收"四件套以 `plan/01-题目文档.md` §4 为准，此处只补**实现级设计**。数值口径的权威定义在 `data/README.md` §4，本文件引用不复写。

## M1 数据契约与剖面 → `timebase.py` / `csvio.py` / `profile.py` + `tools/gen_synthetic_series.py`

> M1 落地记录（2026-10-17，见 `plan/06` D18）：`canon.py` 的 **K2/K3 原语**（`quantize` / `fixed_to_str` / `canonical_json_bytes` / `sha256_hex`）提前到 M1 落地——`profile.json` 的序列化与 `data/truth/hash.txt` 的真值哈希都需要它，"一处定义"胜过三份拷贝；M2 只需补 `build_anomaly_set`。`profile.json` 因此**只含整数与字符串**（值与幅度不进剖面，质量卡只落计数与区间），`canon.assert_hashable` 在落盘出口把关。另：剖面的"缺口区间"（间隔 > `gap_factor × 主导节奏`）与 K7 的 `max_gap_ms` 是两个不同概念，合成数据在 `max_gap_ms` 两侧各留一组合并探针（D18c）。

### `timebase.py`（K5）
- `parse_iso_to_epoch_ms(text, default_tz_offset_min)`：手写日期/时间解析 + **整数** civil↔epoch 换算（Howard Hinnant 的 days_from_civil 算法），返回 UTC 整数毫秒；支持 `YYYY-MM-DD[ T]HH:MM[:SS[.fff]]`、尾随 `Z`、`±HH:MM` 偏移。**禁 `datetime.fromisoformat` 作为唯一通路**：JS 侧要镜像同一算法，故本模块是唯一权威实现。
- `epoch_ms_to_iso(ms)`：由整数反算 `YYYY-MM-DDTHH:MM:SS.mmmZ`（定点宽度，无本地时区、无夏令时的参与）。
- **交叉断言（可证伪）**：测试用 `datetime` 独立复算全量 fixture 行的时间戳，与本模块结果逐行相等——手写算法被标准库证伪过一次才算通过。
- DST/时区纪律：无偏移输入按 `run-spec.timezone_offset_min`（默认 0=UTC）解释并在 `profile.json` 记录；偏移在不同行之间变化（DST 切换）时记录切换点清单；**换算全程整数，不使用本地时区数据库**。

### `csvio.py`
- `load_series(path, spec)` → `Series`（`series_id` + `rows: [(row_no, epoch_ms, value_or_none)]` + 解析统计）。
- 列契约：至少含时间戳列与数值列；列名由 run-spec 的 `timestamp_column` / `value_column` / 可选 `series_id_column` 指定（默认按 `timestamp|time|ts` 与 `value|val|y` 的**白名单同义词表**匹配，歧义即报错不猜）。
- 错误码（`data/README.md` §4.4，错误码表在 `csvio.ERROR_CODES` 单点定义）：`E_EMPTY_FILE`、`E_MISSING_COLUMN`、`E_DUPLICATE_COLUMN`、`E_TS_UNPARSEABLE`、`E_VALUE_UNPARSEABLE`、`E_DUPLICATE_TIMESTAMP`（同 series 重复时间戳超过阈值）、`E_NON_MONOTONIC`。
- **错误必须带源行号**（`row 12: E_TS_UNPARSEABLE: 'xxx'`），且**一次性收集后统一报出**（非首错即停）；坏文件 → exit 2。
- 数值缺失（空串/`NA`/`NaN`）→ `None`，**不补 0、不插值**（缺失本身就是剖面与规则型检测器的输入）。

### `profile.py` → `profile.json`
- 采样节奏：相邻时间差的中位数/众数（**主导节奏**）、间隔分布直方图（分箱规则固定）、不规则度指标。
- 区间清单：重复时间戳、缺口区间（间隔 > `gap_factor × 主导节奏`，`gap_factor` 进 run-spec）、零值段、缺失段、非单调点。
- 数据质量卡：以结构化字段（计数 + 区间）落 `profile.json`，同时在 HTML 首屏渲染成同源可读卡（渲染只消费，不重算）。
- 纯规则计算，不调用模型；JSON 键排序后落盘（K2）。

### `tools/gen_synthetic_series.py`（M1 冻结产物）
- 场景：**"冷链仓储温控与能耗监测（虚构）"**，多指标（`series_id` ∈ 温度 / 湿度 / 能耗），24h 日周期 + 趋势 + 噪声，显式植入四类异常段（尖峰 / 电平漂移 / 方差突变 / 连续缺失-零值段）与已知缺口。
- 确定性 RNG：**splitmix64 自研**（禁 stdlib `random`，跨版本序列不承诺一致），`--seed` 显式传参并写入 manifest。
- 产出（落 `data/synthetic/`、`data/truth/`，冻结禁手改）：
  1. `series.csv` — 长表 `timestamp,series_id,value`（含缺口行与空值行）；
  2. `manifest.json` — 生成参数（seed/周期/幅度/植入段清单）+ 逐文件 sha256 台账（生成器实算）；
  3. `truth.json` — **只存输入与期望**（每段异常的 series/类型/起止行号/植入幅度），期望可由输入独立复算；
  4. `truth/hash.txt` — 真值异常集按 K3 规范 JSON 计算的 sha256。
- 埋点非平凡性：每类异常至少 2 段、至少 1 段落在**窗口边界**（覆盖滚动的边界环视）、至少 1 组**相邻两段间隔略大于与略小于 `max_gap_ms`**（覆盖合并口径两侧）、至少 1 个 `tie` 时间戳样本（覆盖 tie-break）。
- `--check` 通路：重生成到临时目录与冻结产物逐字节比对；**篡改/缺失冻结产物必须 exit 2**（完整性归输入错误）；守门测试两层（冻结产物形态 + 重生成比对）。

## M2 检测内核与 Episode 语义 → `detect.py` / `episodes.py` / `canon.py`

### `detect.py`（4 类检测器，参数面见 `data/README.md` §4.1）
1. `rolling_mad_z(series, window, k)`：滚动中位数 + MAD（`1.4826 × median(|x−med|)`），`|z| > k` 判异常；MAD=0 的特例规则显式定义（写进口径表，不许靠"除以零得到 inf 再比较"）。
2. `rolling_iqr(series, window, iqr_mult)`：滚动 Q1/Q3（线性插值），越出 `[Q1 − m·IQR, Q3 + m·IQR]` 判异常。
3. `stl_resid_z(series, period_points, inner, outer, window, k)`：经典 STL——趋势 = LOESS(全序列)，季节 = 逐相位 LOESS + 低通，bisquare 权重 `(1−w²)²`（**纯乘法，无 `pow`/`exp`**），内循环/外循环次数进 run-spec；残差 z 用滚动中位数+MAD 的同一实现（调用检测器 1 的内部函数，口径不复制）。
4. `rules(series, spec)`：静态阈值、百分比突变（`|x_t/x_{t−1}−1| > pct_jump`，分母为 0/缺失时的规则显式定义）、连续缺失或零值段（长度 ≥ `missing_run`）、CUSUM 两窗均值漂移（`k`/`h`；**累加器只在有效点上推进**）。
- 每个检测器返回 `list[(index, score)]`（score 为原始浮点），**不做阈值外判断以外的任何决策**。
- 缺口/缺失段：规则型检测器按"连续性"判；滚动类检测器在窗口内**有效点计数不足**时该点不高判（阈值 `min_valid` 进 run-spec，禁止默认静默通过）。
- `period_points`：`stl_resid_z` 的周期由**自相关（ACF）估计**或用户声明；估计结果作为**最终生效值**写入 `run.json`（复算消费的是生效值，不重跑估计——避免"估计器实现差异"污染复算）。

### `episodes.py`
- 相邻异常点（按时间序）时间差 `≤ max_gap_ms` 合并为一个 Episode（K7）。
- Episode 字段：`episode_id`、`series_id`、`detector`、`start`/`end`（ISO 定点串）、`start_row`/`end_row`（源行号）、`n_points`、`duration_ms`、`peak_score_q`（定点整数）、`threshold_ref`（触发时生效的阈值/参数快照）。
- 严重度排序键（K6，全部为整数/字符串，禁止用原始浮点排序）：`peak_score_q` 降 → `duration_ms` 降 → `start_row` 升 → `detector` 字典序。
- `episode_id = "<series_id>-E<NNN>"`，NNN 为该 series 内排序后序号（1 起）；同一 run-spec 必得同一组 id。

### `canon.py`
- `quantize(x, decimals)`（半偶舍入到整数）、`fixed_to_str(q, decimals)`（整数构造十进制串）、`canonical_json_bytes(obj)`、`sha256_hex(bytes)`、`assert_hashable(obj)`（拒浮点）——**M1 已落地**（见本节开头的落地记录）。
- `build_anomaly_set(run_spec, prof/rows, episodes)` → 规范 JSON（整数/字符串 only）+ sha256（M2）。
- `run.json` = **解析后的最终参数**（含 ACF 估出的 `period_points`、`max_gap_ms`、`quant_decimals`、算法版本号），是复算的唯一依据；改任一参数必改哈希（写进断言）。

## M3 浏览器内复算验证器（硬门禁）→ `mirror.py` + `mirror/zaa_mirror.js` + `tools/mirror_parity.py`

- `zaa_mirror.js`：手写 JS 实现 `parse`（复用内联已解析的整数毫秒，只做算法）、`detect`（4 类）、`episodes`、`canonicalJson`（键排序 + 整数定点 + LF）、`sha256`（自实现）。
- HTML 内嵌：原始数据（按 series 的行数组，`[ts_ms, value|null]`）+ run.json + 构建时异常集规范 JSON + 构建时 sha256 + 镜像源码。
- 加载时：镜像重跑 → 规范化 → sha256 → 与构建指纹**逐位比较**；同时做**逐点集合比较**。一致 → 绿色 **VERIFIED** 徽章；不一致 → 红色 **MISMATCH** + **首个差异点**（series、下标、期望值、实算值、两侧哈希前缀）。全程零网络请求。
- `tools/mirror_parity.py --html <产物> [--node <exe>]`：用 Node 抽取产物内嵌镜像 + 内联数据执行同一流程，与本机 Python 构建指纹对账。**这是 M3 的可自动化门禁**（浏览器徽章是人读的那一面，Node 对账是机器读的那一面）；Node 缺失 → exit 4 并给两条安装/替代路径；**不允许静默跳过**。
- 篡改探活：`--tamper-index <n>` 故意改一个内联数据点 → 必须 MISMATCH 且定位到该点（探活打在**消费处**：从产物里抽出的内联数据）。

## M4 单文件标注图 → `layout.py` + `render.py`

### `layout.py`（确定性坐标与分箱）
- 主序列视图：y 轴取全序列 min/max（含异常带 padding），x = 行号 → 像素的固定线性映射，坐标**取整到整数像素**；缺口区间、零值段、缺失段的**分箱边界**由固定规则算出，与"正常低值"可区分（缺口 = 显式纹理 pattern，不靠颜色深浅）。
- Episode 卡片：局部放大窗口 = `[start_row − pad, end_row + pad]`，`pad` 进 run-spec；阈值线由该 Episode 的 `threshold_ref` 派生。
- 密度热条：按固定时间分箱（`heat_bin_ms` 进 run-spec）统计 Episode 覆盖度（覆盖点数/分箱内有效点数，**整数比率的定点点数**）。
- small multiples：每 series 一张迷你图，共享同一行号→像素映射规则。

### `render.py`
- `string.Template` 拼装单文件 HTML；内联全部 CSS/JS/数据，**零外链**。
- `assert_no_external_resources(html)` 在函数出口常驻（每次渲染都跑）。
- 组件清单（题面 M4 逐项对应）：主序列 + 异常带 + 峰值标记 + 缺口纹理 / Episode 卡片（局部放大 + 阈值线 + 检测器 + 得分 + 源行号 + `episode_id`）/ 多指标 small multiples / 异常密度热条 / 阈值灵敏度滑杆（前端确定性重算，走同一 JS 内核，滑杆值同步显示为 run-spec 片段）/ 数据质量卡 / 报告区 / VERIFIED-MISMATCH 徽章 / 打印样式（黑白可区分，卡片不截断）。
- 无时钟、无随机；`build_id = sha256(规范 JSON)[:16]`（内容派生）。

## M5 报告层与数字白名单 → `facts.py` + `report.py` + SKILL.md/README

- `facts.py`：从内核结论导出**每条数字都带 `fact_id`** 的台账（异常数、每段峰值/时长/起止行号、最大 z、缺口计数、分箱覆盖度……）；`facts.json` 键排序落盘。
- `report.py`：
  - `extract_numbers(text)` → 数字 token（含中文数字与百分号形态）；
  - `check_report(text, facts)` → 未命中清单（token + 上下文 + 最接近的 fact 值）；未命中即 **exit 1** 并列出，不生成报告；
  - Episode 命名与原因必须引用 `episode_id`（正则门禁：叙事里出现的每个 episode 引用都要能在 `anomalies.json` 里解析到）；
  - **模型禁区由代码门禁而非口头约束**：叙事文本不得引入 `anomalies.json` 之外的 episode、不得出现新的行号。
- SKILL.md：触发条件、四步工作流（profile → detect → render → 指读 HTML + 徽章）、模型分工声明、输入 schema、退出码表、复算口径段。
