# plan/03 模块详设（题面 M1–M5 × 源码模块）

题面模块的"输入 / 输出 / 确定性纪律 / 验收"四件套以 `plan/01-题目文档.md` §4 为准，此处只补**实现级设计**。数值口径的权威定义在 `data/README.md` §4，本文件引用不复写。

## M1 数据契约与剖面 → `timebase.py` / `csvio.py` / `profile.py` + `tools/gen_synthetic_series.py`

> M1 落地记录（2026-10-17，见 `plan/06` D18）：`canon.py` 的 **K2/K3 原语**（`quantize` / `fixed_to_str` / `canonical_json_bytes` / `sha256_hex`）提前到 M1 落地——`profile.json` 的序列化与 `data/truth/hash.txt` 的真值哈希都需要它，"一处定义"胜过三份拷贝；M2 只需补 `build_anomaly_set`。`profile.json` 因此**只含整数与字符串**（值与幅度不进剖面，质量卡只落计数与区间），`canon.assert_hashable` 在落盘出口把关。另：剖面的"缺口区间"（间隔 > `gap_factor × 主导节奏`）与 K7 的 `max_gap_ms` 是两个不同概念，合成数据在 `max_gap_ms` 两侧各留一组合并探针（D18c）。

### `timebase.py`（K5）
- `parse_iso_to_epoch_ms(text, default_tz_offset_min)`：手写日期/时间解析 + **整数** civil↔epoch 换算（Howard Hinnant 的 days_from_civil 算法），返回 UTC 整数毫秒；支持 `YYYY-MM-DD[ T]HH:MM[:SS[.fff]]`、尾随 `Z`、`±HH:MM` 偏移。**禁 `datetime.fromisoformat` 作为唯一通路**：JS 侧要镜像同一算法，故本模块是唯一权威实现。
- `epoch_ms_to_iso(ms)`：由整数反算 `YYYY-MM-DDTHH:MM:SS.mmmZ`（定点宽度，无本地时区、无夏令时的参与）。
- **交叉断言（可证伪）**：测试用 `datetime` 独立复算全量 fixture 行的时间戳，与本模块结果逐行相等——手写算法被标准库证伪过一次才算通过。
- DST/时区纪律：无偏移输入按 `run-spec.timezone_offset_min`（默认 0=UTC）解释并在 `profile.json` 记录；偏移在不同行之间变化（DST 切换）时记录切换点清单；**换算全程整数，不使用本地时区数据库**。

### `csvio.py`
- `load_series(path, spec)` → `Series`（`series_id` + `rows: [(row_no, epoch_ms, value_or_none)]` + 解析统计）。
- 列契约：至少含时间戳列与数值列；列名由 run-spec 的 `timestamp_column` / `value_column` / 可选 `series_id_column` 指定（默认按 `timestamp|time|ts` 与 `value|val|y` 的**白名单同义词表**匹配，歧义即报错不猜）。
- 错误码（`data/README.md` §4.4，错误码表在 `csvio.ERROR_CODES` 单点定义）：`E_EMPTY_FILE`、`E_MISSING_COLUMN`、`E_DUPLICATE_COLUMN`、`E_TS_UNPARSEABLE`、`E_VALUE_UNPARSEABLE`、`E_DUPLICATE_TIMESTAMP`（同 series 重复时间戳超过阈值）、`E_NON_MONOTONIC`。
- **错误必须带源行号**（`row 12: E_TS_UNPARSEABLE: 'xxx'`），且**一次性收集后统一报出**（非首错即停）；坏文件 → exit 2。
- 数值缺失（空串/`NA`/`NaN`）→ `None`，**不补 0、不插值**（缺失本身就是剖面与规则型检测器的输入）。

### `profile.py` → `profile.json`
- 采样节奏：相邻时间差的中位数/众数（**主导节奏**）、间隔分布直方图（分箱规则固定）、不规则度指标。
- 区间清单：重复时间戳、缺口区间（间隔 > `gap_factor × 主导节奏`，`gap_factor` 进 run-spec）、零值段、缺失段、非单调点。
- 数据质量卡：以结构化字段（计数 + 区间）落 `profile.json`，同时在 HTML 首屏渲染成同源可读卡（渲染只消费，不重算）。
- 纯规则计算，不调用模型；JSON 键排序后落盘（K2）。

### `tools/gen_synthetic_series.py`（M1 冻结产物）
- 场景：**"冷链仓储温控与能耗监测（虚构）"**，多指标（`series_id` ∈ 温度 / 湿度 / 能耗），24h 日周期 + 趋势 + 噪声，显式植入四类异常段（尖峰 / 电平漂移 / 方差突变 / 连续缺失-零值段）与已知缺口。
- 确定性 RNG：**splitmix64 自研**（禁 stdlib `random`，跨版本序列不承诺一致），`--seed` 显式传参并写入 manifest。
- 产出（落 `data/synthetic/`、`data/truth/`，冻结禁手改）：
  1. `series.csv` — 长表 `timestamp,series_id,value`（含缺口行与空值行）；
  2. `manifest.json` — 生成参数（seed/周期/幅度/植入段清单）+ 逐文件 sha256 台账（生成器实算）；
  3. `truth.json` — **只存输入与期望**（每段异常的 series/类型/起止行号/植入幅度），期望可由输入独立复算；
  4. `truth/hash.txt` — 真值异常集按 K3 规范 JSON 计算的 sha256。
- 埋点非平凡性：每类异常至少 2 段、至少 1 段落在**窗口边界**（覆盖滚动的边界环视）、至少 1 组**相邻两段间隔略大于与略小于 `max_gap_ms`**（覆盖合并口径两侧）、至少 1 个 `tie` 时间戳样本（覆盖 tie-break）。
- `--check` 通路：重生成到临时目录与冻结产物逐字节比对；**篡改/缺失冻结产物必须 exit 2**（完整性归输入错误）；守门测试两层（冻结产物形态 + 重生成比对）。

## M2 检测内核与 Episode 语义 → `detect.py` / `episodes.py` / `canon.py` / `selftest.py`

> M2 落地记录（2026-10-17，见 `plan/06` D19–D20）：四类检测器 + Episode 语义 + 规范指纹 + 基准套件全部落地，`detect`/`selftest` 退役退出码 3。落地时改了三处**设计措辞**使文档与实跑一致：① `rules` 的 CUSUM 明确为"**对相邻差分**标准化后双侧累加"（`rules` 的参数面里没有窗口，两窗均值法需要窗口，故取差分口径；电平漂移以"跳变"被检，报警后累加器重置）；② `period_points` 的估计从"自相关"细化为**稳妥 ACF**（先剔离群的居中中位趋势残差 + 时间栅格 pairwise ACF + 基频优先 + 跨 series 取中位数）——实测原始序列的 ACF 峰值会漂到 2…302 的任意处；③ 检测器参数在 `run.json`/`anomaly_set` 里以 **6 位定点字符串**落盘（人读的就是被哈希的那一份）。数据侧另有一次**可检出性修复**（humidity 噪声幅度 600→200 milli），真值指纹不变，见 §3.1 第 3 条与 D19。

### `detect.py`（4 类检测器，参数面见 `data/README.md` §4.1）
1. `rolling_mad_z(window, k, min_valid)`：滚动中位数 + MAD（`1.4826 × median(|x−med|)`），`|z| > k` 判异常；窗口为**尾部对齐且含被评点**的 `[i−window+1, i]`；MAD=0 回退到平均绝对偏差、尺度为 0 时该点不高判（口径写在 §4.1，不靠"除零得 inf 再比较"）。
2. `rolling_iqr(window, iqr_mult, min_valid)`：滚动 Q1/Q3（线性插值），越出 `[Q1 − m·IQR, Q3 + m·IQR]` 判异常；IQR=0 时与 MAD=0 同一套回退。
3. `stl_resid_z(inner, outer, window, k, min_valid)`：趋势 = LOESS（一次局部线性 + tricube，窗口由 `period_points` 派生）、季节 = 相位（**栅格下标** mod period）加权均值 + 沿相位轴 LOESS（三倍复制保证周期连续）、外循环用 bisquare 权重 `(1−u²)²`（**纯乘法，无 `pow`/`exp`**）；残差 z 调用检测器 1 的内部实现（口径不复制）。`period_points ≤ 1` = 无季节项。
4. `rules(static_threshold, pct_jump, missing_run, cusum_k, cusum_h)`：静态阈值（`null` = 关闭）、百分比突变（分母为 0/缺失时不表态）、连续缺失**或零值**段（长度 ≥ `missing_run`，得分 = 段长）、CUSUM（相邻有效点差分标准化后双侧累加，报警即重置；差分尺度低于 `10^−quant_decimals ×` 序列尺度时不表态）。
- 每个检测器返回 `list[(index, score)]`（`rules` 另带规则名），**不做阈值外判断以外的任何决策**；缺失值永不参评。
- 缺口/缺失段：规则型检测器按"连续性"判；滚动类检测器在窗口内**有效点计数不足**（`min_valid`，默认 6）时该点不高判。
- `period_points`：run-spec 声明优先；未声明则由**稳妥 ACF** 估计（剔除离群 → 去趋势 → 截尾 → 时间栅格 pairwise ACF → 基频优先），跨 series 取**中位数**作为**最终生效值**写入 `run.json`（复算消费生效值，不重跑估计）；两者都没有 → `1`（无季节项）。估计器**不在哈希路径上**，只需 Python/JS 两侧产出同一个整数生效值。

### `episodes.py`
- 相邻异常点（按时间序）时间差 `≤ max_gap_ms` 合并为一个 Episode（K7），**按 `(series_id, detector)` 分组**合并。
- Episode 字段：`episode_id`、`series_id`、`detector`、`start`/`end`（ISO 定点串）、`start_row`/`end_row`（源行号）、`n_points`、`duration_ms`、`peak_score_q`（定点整数）、`threshold_ref`（该族检测器的生效参数块快照）。
- 严重度排序键（K6，全部为整数/字符串，禁止用原始浮点排序）：`peak_score_q` 降 → `duration_ms` 降 → `start_row` 升 → `detector` 字典序。
- `episode_id = "<series_id>-E<NNN>"`，NNN 为该 series 内排序后序号（1 起）；同一 run-spec 必得同一组 id。

### `canon.py`
- `quantize(x, decimals)`（半偶舍入到整数）、`fixed_to_str(q, decimals)`（整数构造十进制串）、`canonical_json_text/bytes`、`sha256_hex`、`canonical_digest`、`assert_hashable`（拒浮点）——**M1 已落地**（见本节开头的 M1 落地记录）；`_power_of_ten` 用连乘替代 `10 ** d`（K4 扫描门实测抓出并修掉）。
- `build_anomaly_set(run, episodes, summary)` → 规范 JSON（整数/字符串 only）+ sha256（M2）。**`run` 块在指纹里**：只哈希 episode 列表会让"改任一参数必改哈希"在"参数改了但判定没动"时失效。
- `run.json` = **解析后的最终参数**（含 ACF 估出的 `period_points`、`max_gap_ms`、`quant_decimals`、算法/规范版本号），是复算的唯一依据；改任一参数必改哈希（selftest 与 `tests/test_detect.py` 双处断言，后者对整个参数面逐项扫）。

### `selftest.py`（基准套件）
五项检查，每项都带**可证伪探针**（探针不能变红即计为该检查失败——否则整套可能因为"什么都没查"而全绿）：

| 检查 | 断言 | 探针（必须变红） |
| --- | --- | --- |
| `frozen-artifacts-ledgered` | manifest 台账覆盖四个冻结产物且逐一 sha256 相等、`hash.txt` 与 `truth_sha256` 一致 | 复制一份产物翻转一个字节 → 必须报"tampered" |
| `truth-reconciliation` | 39 段植入异常**逐段**被至少一个 episode 覆盖；6 条合并探针在 `rolling_mad_z` 上两侧可判定且与 `expected_merged` 一致 | 追加一段"任何检测器都不可能覆盖"的植入段 → 必须点名报缺失 |
| `fixture-digest-frozen` | 默认 spec 下异常集指纹 == 冻结黄金字面量 | 与另一个字面量比较必须不等 |
| `parameter-change-moves-digest` | `k`/`iqr_mult`/`inner`/`missing_run`/`max_gap_ms`/`period_points` 各自改动后指纹必变 | 同一 spec 重跑指纹必须**不变**（比较不能是"永远不等"） |
| `profile-double-run-byte-identical` | M1 的双跑逐字节一致仍然成立 | 改 `timezone_offset_min` 后字节必须变 |

- 崩溃的检查按"失败"上报（不吞、不静默跳过）；找不到冻结数据 → **exit 4**（环境前提不满足），不是 exit 0。
- 探针的**方向**很关键：覆盖类检查的探针必须**增加**一项无法满足的要求（删一段只会让要求一起消失，检查照样绿）。

## M3 浏览器内复算验证器（硬门禁）→ `mirror.py` + `mirror/zaa_mirror.js` + `render.py`（嵌入契约 + 最小载体页）+ `tools/mirror_parity.py`

> M3 落地记录（2026-10-17，见 `plan/06` D21）：三处实现口径在落地时定稿，都是"让不该进哈希的东西进不来 / 让红必须能指认自己"：① **内联样本以十进制文本落盘**（`repr(value)` 的最短往返串，镜像按"最近双精度"解析还原），因此整份 payload 仍是"整数 / 字符串 / null"，`canon.assert_hashable` 照样把关——若直接内联浮点字面量，就等于给 K3 开一个例外；② **镜像消费 `run.json` 的生效参数**（含 `period_points`；十进制参数按 6 位定点串还原），**不重跑周期估计**——K8/D13 的收益在此兑现；③ **`verify` 与 `tools/mirror_parity.py` 共用一份实现**（后者直接调 `mirror.cmd_verify`）：一个能与命令互相矛盾的门禁工具比没有工具更糟。
>
> 另一处实测发现值得记（与 M2 那条"1 条最初仍绿"同类）：把镜像的半偶舍入边界从 `frac > 0.5` 改成 `frac > 0.4999995`，**冻结数据的指纹对账仍然全绿**——没有分数落进那个 5e-7 宽的口子。于是补了一组**跨语言定点向量**（`mirror.FIXED_POINT_VECTORS` + 并列字面量 `FIXED_POINT_TIES`），由 Node 跑镜像的 `quantize` / `fixedToStr` 与 `canon` 逐项对账；那条变异如今在这组向量上变红（15 条变异全红的记录见 `plan/05` M3 状态列）。
>
> 第三条实测教训来自**浏览器通道**（Node 通道测不到，因为它直接驱动镜像、从不跑 boot 脚本）：boot 脚本里写了 `$payload_id` 想交给外层 `string.Template` 替换，而**被替换进去的值不会再被扫描一次**，于是那个槽位原样进了产物、页面去取一个 null 元素，徽章永远停在"复算中…"。修法是在构造期就把它拼进字面量（`_BOOT_JS_TEMPLATE % SCRIPT_ID_PAYLOAD`），并补两条测试：产物里**不得出现任何 `$`**（槽位逃逸 = 红），以及 boot 块必须按契约 id 取 payload 块。15 条变异里那条"把槽位写回去"就是这条测试的靶子。**教训**："机器读的那一面全绿"不等于"用户看到的那一面成立"，人读通道得真去打开一次。

### `mirror/zaa_mirror.js`（手写 JS 镜像）
- 单文件、无依赖、无 DOM、无网络 API、无 Web Crypto；`mirrors:` 行逐族指名对应的 Python 模块与函数（`canon` / `timebase` / `detect` / `episodes`）。K4 的 JS 词法门自动覆盖它（文件在 `src/anomaly_atlas/` 下，`tests/test_no_transcendental.py` 直接扫），另有测试钉住"它确实在扫描范围内"。
- `ZAA.recompute(payload)`：4 类检测器 → Episode 合并 / 严重度排序 / `episode_id` → 汇总 → 规范 JSON（键排序 + 2 空格缩进 + LF + 结尾换行）→ 自实现 SHA-256（连 UTF-8 编码也是手写，含成对代理与多字节）。另暴露 `quantize` / `fixedToStr` / `canonicalJsonText` / `utf8Bytes` / `sha256Hex` / `verdict`。
- **不重实现时间解析**（内联的已是整数毫秒，K5）与**周期估计**（消费 `run.json` 的生效值，K8/D13）；栅格下标 `(ts − ts0) / cadence` 与 cadence 都从内联数据 / run.json 取。

### 内嵌契约（`render.py` 落地，M4 复用）
- 三个 `<script>` 块，一个块一件事：`zaa-payload`（输入 blob）、`zaa-mirror`（镜像源码**逐字节内联**）、`zaa-boot`（重算 → 比较 → 徽章）。块体前后不加换行，所以"产物里那段源码"与 `zaa_mirror.js` 逐字节相等（有测试钉住这一条）。
- `zaa-payload` 内容：生效 run 文档（`run.json` 原文）+ 按 series 的行数组 `[epoch_ms, 数值文本|null, 源行号]` + **构建时检测点**（按 `(series, detector)` 展平、得分已定点化）+ 构建时规范 JSON（异常集全文）+ 构建时 sha256 + 契约 / 镜像版本号。
- M3 只落**最小载体页**（`examples/atlas.html`，构建命令 `tools/mirror_parity.py --build`）：标题、徽章、构建指纹 / 复算指纹 / 首个差异点、契约说明。它的唯一职责是让复算门禁可机器复跑；**完整标注图是 M4**，复用同一契约。
- 判定与定位（`ZAA.verdict`）：先比规范 JSON 的 UTF-8 字节（给出首个不同字节偏移），再**逐点集合比较**（报到"哪个 series / 哪个 detector / 第几个点 / 期望与实算"）。徽章 = VERIFIED / MISMATCH + 首个差异点。
- 零外链（K12）：`assert_no_external_resources` 在构建出口常驻；脚本体先屏蔽再扫标记（JS 的块注释与运算符号不是外链），同时扫脚本体里有无网络 API（`fetch` / `XMLHttpRequest` / `WebSocket` / `EventSource` / `importScripts` / `sendBeacon`）；`url()` 只放行 `data:`。

### `mirror.py`
- `load_mirror_js` / `extract_artifact`（按 id 取回 payload 与镜像源码）/ `expected_block` / `tamper_payload` / `run_node_mirror`（把产物自带镜像、payload、期望三份数据交给 Node）/ `run_node_fixed_point`（定点向量门）/ `verify_artifact`（CLI 与工具共用的那一份判定）/ `cmd_verify`。
- Node 缺失 → **exit 4** 且给两条补救路径（装 Node / 走浏览器徽章），**不静默跳过**；产物不是本契约的产物（缺块 / JSON 坏）→ exit 2；镜像跑不起来（崩溃 / 没打印结果）→ exit 1（缺陷），与 mismatch 区分开。
- `SHA256_VECTORS` 单点定义，Python 侧与本页 JS 侧共用；向量在 harness 里**先于**重算执行——判定所依赖的那个哈希本身先被验一次（向量不过关按缺陷上报，不算 mismatch）。

### 篡改探活（打在消费处）
- `--tamper-index <n>` 位移第 n 个**内联样本**（顺序 = 产物里 series 的存储顺序、再行序；位移量 = 该 series 自身跨度 `× 1000`，常数序列回退 10^6），然后要求"必变红 **且**首个差异点落在被篡改的那个 series"。
- 探针没变红（篡改没推动结果）或红了却指不到那个 series，都按**探针失败**上报（exit 1），不算通过——一个无法把自己的红归因到"我注入的那个缺陷"的门禁，可能是红在自己坏了。

### `tools/mirror_parity.py`
- `--html <产物> [--node <exe>] [--tamper-index <n>]`：机器读的那一面；`--build <out.html> [--csv] [--spec]`：落 M3 最小载体页（CI 先构建再验，避免"验的是一个手维护的文件"）。
- 退出码与 `verify` 一致（0 / 1 / 2 / 4），因为判定就是同一份实现。


## M4 单文件标注图 → `layout.py` + `render.py`

### `layout.py`（确定性坐标与分箱）
- 主序列视图：y 轴取全序列 min/max（含异常带 padding），x = 行号 → 像素的固定线性映射，坐标**取整到整数像素**；缺口区间、零值段、缺失段的**分箱边界**由固定规则算出，与"正常低值"可区分（缺口 = 显式纹理 pattern，不靠颜色深浅）。
- Episode 卡片：局部放大窗口 = `[start_row − pad, end_row + pad]`，`pad` 进 run-spec；阈值线由该 Episode 的 `threshold_ref` 派生。
- 密度热条：按固定时间分箱（`heat_bin_ms` 进 run-spec）统计 Episode 覆盖度（覆盖点数/分箱内有效点数，**整数比率的定点点数**）。
- small multiples：每 series 一张迷你图，共享同一行号→像素映射规则。

### `render.py`
- `string.Template` 拼装单文件 HTML；内联全部 CSS/JS/数据，**零外链**。
- `assert_no_external_resources(html)` 在函数出口常驻（每次渲染都跑）。
- 组件清单（题面 M4 逐项对应）：主序列 + 异常带 + 峰值标记 + 缺口纹理 / Episode 卡片（局部放大 + 阈值线 + 检测器 + 得分 + 源行号 + `episode_id`）/ 多指标 small multiples / 异常密度热条 / 阈值灵敏度滑杆（前端确定性重算，走同一 JS 内核，滑杆值同步显示为 run-spec 片段）/ 数据质量卡 / 报告区 / VERIFIED-MISMATCH 徽章 / 打印样式（黑白可区分，卡片不截断）。
- 无时钟、无随机；`build_id = sha256(规范 JSON)[:16]`（内容派生）。

### M4 落地口径（2026-10-18 实测；与设计的三处差异在此说明）

- **API 名**：`layout` = `resolve_render_spec` / `value_bounds` / `row_to_pixel` / `value_to_pixel` / `region_spans` / `threshold_values` / `main_series_layout` / `episode_zoom_layout` / `density_bins` / `small_multiples_layout`；`render` = `build_payload`（M3 契约一字不变）/ `build_view_html` / `write_view` / `cmd_render` / `assert_no_external_resources` / `assert_no_template_slots`（M3 的 `write_carrier` / `build_carrier_html` / `CARRIER_TITLE` 随产物替换改名，调用方与测试同提交改到）。
- **三类纹理落在几何层，不是样式层**：缺口 = 斜纹线段（在矩形内按 3:1 截断；**不用 `clip-path`**——那是 `url(...)` 引用，K12 只放行 `data:`）、零值段 = 零点上下 ±5 px 的竖栅、缺失段 = 虚线框且无纹理。三者互相可区分由**结构**保证，黑白打印天然成立（P5）；`layout` 的返回结构里**没有任何浮点数**（`tests/test_layout.py` 用 `conftest.iter_floats` 逐层断言）。
- **缺口必须就地加宽**：x 轴是行号 → 像素，时间缺口在行号空间只有 1 像素宽，所以按"缺席样本数 × 局部行密度"把标注带加宽（加宽的是**标注**，映射本身不动）。
- **阈值线一律从 `threshold_ref` 派生**：z 类 = `median ± k·robust_scale`（尾窗 = 该段峰值行的 detector 窗口）、四分位类 = `Q1/Q3 ∓ m·IQR`（退化箱回退 MAD 尺度，与检测器同口径）、`rules.static_threshold` = `±level`；`pct_jump` / `cusum` / `missing_run` / `zero_run` **没有数值线**，卡片如实写明并原样打印 `threshold_ref`（不画一条无从推导的线）。
- **呈现参数不进指纹（D22）**：`pad_rows` / `heat_bin_ms` 走独立的 render run-spec（`--spec` 里的 `"render"` 块），resolve 后记录在产物页面上；`run.json` 与异常集指纹**不变**——否则"改一个与判定无关的呈现参数就改档案指纹"会把 K8 的"改参数必改哈希"稀释成"改任何字都改哈希"。
- **滑杆**：`k_scale`（50…150%，基线 100%）乘三个滚动类检测器的阈值参数、`max_gap_ms` 两档；实现是**深拷贝 payload → 改 `run.params`（十进制仍写 6 位定点串）→ 调 `ZAA.recompute`**，滑杆值经 `ZAA.canonicalJsonText` 渲染成 run-spec 片段。构建指纹保持不可变，滑杆结论单独成块；**基线下复算必须等于构建指纹**（浏览器实测 `100% / 1800000` → `6020a3d3…`）。
- **主序列的选择是确定的**：Episode 数最多的 series，并列取 `series_id` 字典序最小（`render._primary_series`，单测钉住），不依赖 dict 迭代序。
- **页面固定浅色渲染**（`:root { color-scheme: light }`）：标注图是面向打印的报告，色深/灰阶在纸上的含义必须与屏幕上一致（有测试钉住这一条）。
- **零外链在产物层面断言，且浏览器实测**：`performance.getEntriesByType("resource").length == 0`。同理，`--narrative` 里带 `https://` 或 `$` 会被**构造期**拦下（exit 2 / ValueError），不是"写进页面再说"。

## M5 报告层与数字白名单 → `facts.py` + `report.py` + SKILL.md/README

- `facts.py`：从内核结论导出**每条数字都带 `fact_id`** 的台账（异常数、每段峰值/时长/起止行号、最大 z、缺口计数、分箱覆盖度……）；`facts.json` 键排序落盘。
- `report.py`：
  - `extract_numbers(text)` → 数字 token（含中文数字与百分号形态）；
  - `check_report(text, facts)` → 未命中清单（token + 上下文 + 最接近的 fact 值）；未命中即 **exit 1** 并列出，不生成报告；
  - Episode 命名与原因必须引用 `episode_id`（正则门禁：叙事里出现的每个 episode 引用都要能在 `anomalies.json` 里解析到）；
  - **模型禁区由代码门禁而非口头约束**：叙事文本不得引入 `anomalies.json` 之外的 episode、不得出现新的行号。
- SKILL.md：触发条件、四步工作流（profile → detect → render → 指读 HTML + 徽章）、模型分工声明、输入 schema、退出码表、复算口径段。

### M5 落地口径（2026-10-18 实测；与设计的三处差异在此说明）

- **`facts.py` 的 API** = `Ledger`（`add`/`add_int`/`add_fixed`/`add_text`/`entries`，**重复 `fact_id` 直接报错**而不是覆盖）+ `scaled_value`（整数与定点串归一到同一标尺）+ `numeric_index`（`{缩放值 → [fact_id…]}`，同值多 id 是合法状态）+ `build_facts(run_document, anomaly_set, profile_document=None, rows_by_series=None, heat_bin_ms=None)` + `ledger_summary`。台账**不读 CSV、不跑检测器**：数据全部来自已有结论（`anomaly_set` / `run_document` / `profile`），符合"报告数字是引用而非重算"。
- **台账覆盖面**（实测 1861 条事实 / 1682 条数值 / 178 个 episode id）：聚合计数（`episodes.total` / `detections.total` / 点数与时长之和 / 最高峰值得分）、每检测器流（`detector.<name>.n_points` / `n_episodes`）、每 series（行数 / 有效与缺失值 / 采样节奏 / 首末时间戳 / 栅格格数 / Episode 数 / 缺口·零值段·缺失段数 / 零值·负值数 / 时间跨度）、每 Episode（峰值 / 时长 / 点数 / 起止行号 / 起止 epoch 毫秒 / 检测器）、**生效参数**（`detector.<name>.<param>` 与 `run.<param>`，保持 `run.json` 的落盘形态）、数据质量计数（`quality.*`）、**密度热条分箱**（`render.heat_bin_ms` / `bins.total` / `bin.<i>.n_valid·n_covered·coverage_q·start_ms`）。
- **台账里没有 ISO 串**：Episode 的起止以 `start_ms`/`end_ms`（整数 epoch 毫秒）落盘，ISO 只出现在 `anomalies.json`（K2）。`report` 侧把叙事里的 ISO 时间戳**换算成毫秒**再比对，所以"照页面上的时间引用"仍然可被门禁接受，而产物形态不变。
- **分箱复用同一实现**：`bin.<i>.coverage_q` 由 `layout.density_bins` 产出（与页面上那条热条同一函数、同一输入、同一分箱宽度），因此叙事引用的覆盖率与读者看到的条带不可能不一致。
- **`report.py` 的 API** = `extract_numbers` / `extract_episode_refs` / `extract_row_refs` / `check_report` / `audit` / `gate_summary` / `render_violations` / `load_facts` / `validate_facts` / `cmd_check_report` + 异常类 `NarrativeRejected`（携带 violations）。
- **掩码而非减法**：抽取前先把 **ISO 时间戳、`CSV 行 N`/`文件行 N`、episode 引用、`row N`/`行 N`/`第 N 行`** 从文本里挖掉（用等长空白替换，偏移量不变），所以它们内部的数字不会被误当成报告数字；四类各有自己的门。
- **`row N` 与"物理行"分家**：`row N`/`第 N 行` 必须在**档案出现过的行号**里（Episode 起止行）；`CSV 行 N`/`文件行 N` 明确标成解析层面的物理行，**两类门都不管**——这正是题面允许的"既有引用"豁免，且必须在文本里标出来。
- **百分号可以命中比值**：`42.34%` 既匹配"值 42.34 的事实"也匹配"值 0.423400 的比值事实"（定点整数除法，精确）。中文数字**必须带量词**（`三处`/`十五条` 计入；`统一`/`一般`/`十分` 不计入）——这是刻意的假阳性妥协，理由与代价写在 `plan/自评表.md` 第五节。
- **`render --narrative` 在构造期跑门禁**：`build_view_html` 里建台账并 `check_report`，有未命中就 `raise NarrativeRejected`；`cmd_render` 捕获后**逐条打印全部未命中**并返回 exit 1，**一个字节都不写**。因此不存在"带着未校验报告出品"的代码路径（题面 M5 的"报告生成中止"）。
- **`detect` 同步落 `facts.json`**：`--out-dir` 的帮助文本早就承诺了 `facts.json`，M5 把它兑现（run.json / anomalies.json / facts.json / anomaly_set.sha256）。台账用的展示分箱宽度是 `layout.DEFAULT_HEAT_BIN_MS`，并且分箱只是**呈现聚合**，所以不进指纹（D22 不变）。
- **最后一个退出码 3 退役**：`STAGE_NOT_READY` 清空 → **删除 `cli.EXIT_NOT_READY` 常量** → `test_skeleton.py` 的 `TestStageNotReadyRegistry` 整类退役、换成 `TestExitCodeThreeIsRetired`（跑遍每个命令，断言"没有任何命令答 3"，`selftest` 因成本只做结构断言）→ README 与 `plan/00·02·03·05·06` 回写 → 决策记录 D23。
- **`selftest` 从 5 项变 6 项**：新增 `report-number-whitelist`（用台账自己的引用拼一段叙事，必须过；探针注入一个**先验证不在台账里**的编造数字 + 编造 episode + 编造行号，要求三类各被指名拒绝且逐个列出）。改这个数字是刻意的两处编辑（`selftest.CHECKS` 与 `tests/test_selftest.py` 的字面量）。
